# M2 wave 5 research — `env`: the environment data a writer consumes

Scope: what the HTML writer (wave 5) reads out of sphinx-ultra's `BuildEnvironment`
and resolve pass, how each piece is shaped today, how it differs from what Sphinx
9.1.0's `StandaloneHTMLBuilder` reads, the toctree-resolution port that is missing,
the URI/Builder abstraction that is missing, and every entry of the
`tests/env_differential.rs` exemption tables mapped to the wave-5 work item that
closes it.

Notation: `crate:` paths are relative to `/home/user/sphinx-ultra`. `SP/` =
`…/site-packages/sphinx`, `DU/` = `…/site-packages/docutils` (Sphinx 9.1.0,
docutils 0.22.4, the pinned uv archive). All "probe" results were produced by
running real Sphinx under
`PYTHONNOUSERSITE=1 uv run --python 3.12 --with 'sphinx==9.1.0' --with 'docutils==0.22.4'`
in `scratchpad/probe-env/` (scripts `probe1.py`…`probe5.py`, outputs `out_html*.txt`).

## 0. Executive summary (the load-bearing findings)

1. **Every env structure the writer needs already exists and is oracle-exact**
   (`tocs`, `toc_num_entries`, `toctree_includes`, relations, `titles`,
   `toc_secnumbers`, `toc_fignumbers`, std/py registries, `index_entries` →
   genindex, py-modindex). What does NOT exist: a builder/URI abstraction, the
   toctree *resolution* (`_resolve_toctree` & friends), tag evaluation for
   `only`, `get_objects()` producers for `objects.inv`, and several env
   registries the HTML builder reads (`env.images`, `env.dlfiles`, math
   equations, citations).
2. **URIs are hard-coded to Sphinx's DummyBuilder answer (`''`)** in two places:
   `crate:src/builder.rs:1309` (`relative_uri = |_from, _to| String::new()` in
   `xref_phase`) and `crate:src/builder.rs:1260` (`rel_uri = |_| Some(String::new())`
   in `genindex_phase`). The plumbing is already closure-shaped
   (`Resolver.relative_uri: &dyn Fn(&str,&str)->String` at
   `crate:src/env/resolve.rs:104`; `create_index(rel_uri: &dyn Fn(&str)->Option<String>)`
   at `crate:src/env/genindex.rs:355`; `InventoryFile::dump(get_target_uri: impl Fn(&str)->String)`
   at `crate:src/inventory.rs:347`), so a `Builder`/`TargetUris` object with
   `dummy`/`html`/`dirhtml` implementations is a narrow, mechanical change — but
   the env oracle MUST keep running under the dummy policy (its fixture has
   `refuri=""` everywhere). The only other URI code in the tree,
   `crate:src/utils.rs:563 relative_uri` (pathdiff-based, appends a suffix) and
   `crate:src/html_builder.rs:525/530`, is **not** Sphinx's algorithm and must not
   be reused (e.g. it returns `index.html` for index→index where Sphinx returns `''`).
3. **Toctree resolution is the single biggest env-side gap.** 28 of the 43
   `KNOWN_RESOLVED_GAPS` entries and the `toctree_circular` `KNOWN_WARNING_GAPS`
   entry close with a faithful port of `SP/environment/adapters/toctree.py`
   `_resolve_toctree` (+ `_entries_from_toctree`, `_toctree_entry`,
   `_toctree_*_entry`, `_toctree_add_classes`, `_toctree_copy(_seq)`). The same
   port yields `document_toc` (local TOC, sidebar `toc`) and
   `global_toctree_for_doc` (template `toctree()`). Every input it needs is in the
   environment already; it additionally needs builder tags (for `only`) and the
   URI policy. §11 is a porting spec.
4. **`longtitles` is a separate clone of `titles`** (`crate:src/builder.rs:979-984`)
   and numbering stamps `secnumber` onto `env.titles` only
   (`crate:src/env/numbers.rs:189-191,267-269`). In Sphinx they are *the same
   object* (`SP/environment/collectors/title.py`: `longtitlenode = titlenode`),
   so the HTML `<title>` of a numbered page is `1. A &#8212; …` (probe). The writer
   must read a secnumber-stamped longtitle.
5. **Attribute encodings the writer must decode:** `secnumber` is
   `AttrValue::List(["1","2"])` or the docutils-None sentinel `AttrValue::Str("True")`
   (`crate:src/env/numbers.rs:287-292`) — "True" must read as *no number*;
   `toctree['caption']` is `"True"` when absent (`crate:src/rst/block.rs:6005-6009`);
   `toctree['entries']` is a list of Python tuple *reprs* like `"('T', 'a')"`
   that must be parsed back (`crate:src/env/toctree.rs:149-162`).
6. **HTML-visible read-side gaps that change what the writer sees:** docinfo field
   list not removed (Sphinx pops it); `PropagateTargets`/`MoveModuleTargets`/
   `ReorderConsecutiveTargetAndIndexNodes` not applied in-tree (so
   `node['ids'][0]` on figures ≠ the key `toc_fignumbers` uses); `AutoNumbering`
   missing (captioned unlabeled figures get no id → Sphinx numbers them, and the
   HTML translator would warn `Any IDs not assigned for figure node`);
   `FilterSystemMessages` / `SphinxSmartQuotes` absent (both `KNOWN_INERT_CONF`
   keys become live for HTML).
7. **Sidebar `toctree()` re-emits toctree warnings per page.** Probe with real
   `sphinx-build -b html` (default theme alabaster): a toctree pointing at a
   title-less document emitted the `toc.no_title` warning **7 times** (once at
   write-time resolution of `index`, once per page rendered with the navigation
   sidebar, genindex/search pages included). Warning-stream parity for HTML needs
   the template `toctree()` to call the same resolver with the same warning sink.
8. **Placeholder-HTML cache coupling:** `read_one_file` treats an empty cached
   `html` as a cache miss (`crate:src/builder.rs:844`). Once rendering moves to the
   write phase (it must — it needs whole-project state), that check turns every
   warm build into a full re-parse unless changed.

## 2. The toctree graph

### 2.1 `env.tocs[docname]` — yes, a doctree-shaped `bullet_list`

Built by `crate:src/env/toctree.rs:424 build_toc` (port of
`TocTreeCollector.process_doc` / nested `build_toc`), called from
`merge_phase` (`crate:src/builder.rs:1011-1018`). Shape (probe + oracle):

```
<bullet_list>
    <list_item>
        <compact_paragraph>
            <reference anchorname="" internal="1" refuri="index">   ← refuri = the OWNING docname
                Index
        <bullet_list>
            <toctree caption="True" entries="(None,\ 'a') (None,\ 'b')" glob="0" hidden="0" includefiles="a b" includehidden="0" maxdepth="-1" numbered="999" parent="index" rawentries="" titlesonly="0">
            <list_item>
                <compact_paragraph>
                    <reference anchorname="#sub-of-index" internal="1" refuri="index">
                        Sub of index
                <bullet_list>
                    <only expr="html">
                        <toctree …>
```

Rules the port relies on (all in `build_toc_level`, `crate:src/env/toctree.rs:431-491`):
- one `list_item > compact_paragraph > reference` per section; `anchorname` is `''`
  for the document's FIRST entry and `'#' + ids[0]` afterwards
  (`make_anchor_name`, `:603-613`); `refuri` = the docname (rewritten only at
  resolution time); `internal="1"`.
- nested sections → nested `bullet_list` inside the `list_item`.
- `only` nodes → a fresh `only expr=…` wrapper holding the entries
  (`:464-474`); tag filtering is deferred to copy/resolution time.
- `toctree` nodes anywhere inside non-section elements are **shallow-copied**
  into the section-level entry list (`collect_body_entries`, `:513-516`), i.e. a
  toctree sits *beside* `list_item`s inside a `bullet_list`.
- object descriptions contribute `compact_paragraph skip_section_number="1" >
  reference > literal(_toc_name)` entries (`object_toc_entry`, `:567-598`),
  nested per `memo_parents` (`:503-561`).
- empty document → empty `<bullet_list>` and `toc_num_entries = 0` (`:424-429`).
- after numbering (§4), references carry `secnumber` (see §4.2).

### 2.2 `toctree` node attributes (as the resolver must read them)

`compound classes="toctree-wrapper"`.

### 2.3 `toctree_includes`, `files_to_rebuild`, `glob_toctrees`, `numbered_toctrees`

`note_toctree` (`crate:src/env/toctree.rs:657-679`) = `SP/environment/adapters/toctree.py:32-47`,
called once per toctree copy in toc order (`toctree_copies`, `:684-696`). The key is
created even for an empty toctree (setdefault semantics). Oracle example
(`toctree_numbered`): `toctree_includes = {'index': ['a','b']}`,
`files_to_rebuild = {'a': ['index'], 'b': ['index']}`.

Virtual docnames (`VIRTUAL_DOC_NAMES = ["genindex","modindex","search"]`,
`crate:src/env/toctree.rs:54`) ARE in `toctree_includes`/`includefiles` — same as
Sphinx. Consequence (probe1): `relations` contains `'genindex'` as a node, e.g.
`'sub/c': ['sub/b','sub/b','genindex'], 'genindex': ['index','sub/c',None]`.

### 2.4 Relations

`collect_relations` (`crate:src/env/toctree.rs:714-725`) over the guarded
iterative `traverse_toctree` (`:752-776`) → `docname → (parent, prev, next)`
(`Relation` type `:704`). Derived, never stored (snapshot computes it,
`crate:src/env/mod.rs:475-478`). Matches `SP/environment/__init__.py:778-795`
except that a mutual cycle terminates here where Sphinx raises `RecursionError`
(the oracle records `relations: null` for `toctree_circular`; a real
`sphinx-build -b html` **crashes** on that project in `prepare_writing`, which
calls `collect_relations`, `SP/builders/html/__init__.py:492`).

How `get_doc_context` consumes relations (`SP/builders/html/__init__.py:564-605`):
- `next`: `related[2]` → `{'link': get_relative_uri(docname, next), 'title': render_partial(titles[next])['title']}` and appends `(next, title, 'N', _('next'))` to rellinks — **inside a `try: … except KeyError`**, so a next of `genindex` (no title) yields *no* next link and no rellink (probe1: `sub/c.html` has only index/modules/previous).
- `prev`: same with `'P'`, `_('previous')`, appended AFTER next.
- `parents`: walk `related[0]` up through `relations`, append `{'link','title'}` (KeyError suppressed per step), then `parents.pop()` (drop the root) and reverse. Probe1 `sub/c.html`: `nav-item-1` = `b.html` "2. B".
- A document not reachable from the root has no relation entry → no prev/next/parents.

### 2.5 Ancestors

`toctree_ancestors` (`crate:src/env/toctree.rs:792-813`) = `_get_toctree_ancestors`
(`SP/environment/adapters/toctree.py:562`); the docname itself first, stops on a
cycle; empty for a document with no toctree parent. Last parent in sorted
`toctree_includes` order wins (Sphinx sorts the dict before writing,
`SP/builders/__init__.py:735`). Used by `_resolve_toctree` for membership only.

## 3. Titles and longtitles

- `document_title` (`crate:src/env/toctree.rs:944-958`): a fresh `title` node
  whose children are the first section title's children filtered through
  `SphinxContentsFilter` (`filter_title_children`, `:620-646`); `<no title>` text
  when there is no section. Stored under both keys in `merge_phase`
  (`crate:src/builder.rs:979-984`) **as two clones**.
- Sphinx (`SP/environment/collectors/title.py`, `process_doc`): `longtitlenode =
  titlenode` (same object) unless `'title' in doctree` (the docutils `title`
  directive — not implemented in this crate, so longtitle ≡ title always).
- Numbering stamps `secnumber` on `env.titles[doc]` only
  (`crate:src/env/numbers.rs:177-191,267-269`). Because Sphinx's two maps alias,
  the stamp is visible through `longtitles` too, and the page title shows it.
  Probe1 (`sphinx-build`-equivalent html build, numbered toctree):
  `<title>1. A &#8212; fixture 1.0.0 documentation</title>`,
  `<link rel="next" title="2. B" href="sub/b.html" />`,
  `<li class="nav-item nav-item-this"><a href=""><span class="section-number">1. </span>A</a></li>`.
  **Fix options:** make `longtitles` `Option`-valued ("same as titles") or stamp
  both maps in `walk_toc`. `snapshot()` exports `longtitles_pformat`
  (`crate:src/env/mod.rs:490`) but the oracle fixture has no longtitles key, so
  nothing pins it today.
- `render_partial(title)['title']` output includes the secnumber span because
  `HTML5Translator.visit_title` calls `add_secnumber` (`SP/writers/html5.py:427-433`):
  `<span class="section-number">1. </span>` (suffix `html_secnumber_suffix`, default `'. '`).
  In the `<link title=…>`/`title=` attributes the template applies `striptags`, yielding `1. A`.
- `clean_astext` (`crate:src/env/numbers.rs:514-531`) drops `raw`, blanks image
  alt — used for `:doc:` captions and must be used for std `get_objects` doc
  dispnames (`SP/domains/std/__init__.py:1335`: `clean_astext(self.env.titles[doc])`,
  probe: `orph std:doc -1 orph.html <no title>`).

## 4. Numbering data

### 4.1 Shapes
- `toc_secnumbers[doc][anchorname] = Vec<u32>`; anchorname `''` for the doc's top
  entry, `'#id'` otherwise; entries past the `:numbered:` depth get `[]` (Sphinx:
  `()`), `crate:src/env/numbers.rs:253-266`. Oracle: `{'a': {'': [1], '#sub': [1, 1]}, 'b': {'': [2]}}`.
  The container of a numbered toctree is itself never numbered.
- `toc_fignumbers[doc][figtype][fig_id] = Vec<u32>`; figtypes `figure`, `table`,
  `code-block`, `displaymath` (`figtype_of`, `:461-470`). Oracle:
  `{'a': {'code-block': {'code-a': [1]}, 'figure': {'fig-a': [1]}, 'table': {'tab-a': [1]}}}`.
  `fig_id` is `ids[0]` **after** `PropagateTargets` (replayed via
  `PropagatedIds::effective_ids`, `crate:src/env/std_domain.rs:587-619`).

### 4.2 `secnumber` attribute encoding (writer must decode)
`secnumber_attr` (`crate:src/env/numbers.rs:287-292`): `Some(n)` →
`AttrValue::List(["1","1"])` (pformat `secnumber="1 1"`), `None` (past depth) →
`AttrValue::Str("True")` (docutils' rendering of a None attribute). The HTML
translator tests `node.get('secnumber')` for truthiness
(`SP/writers/html5.py:357-360` for references: `('%s' + secnumber_suffix) % '.'.join(...)`,
no span; `:406-433` for titles: `<span class="section-number">…</span>`). So the
writer must treat `Str("True")` as falsy and `List` as `'.'.join`. Same for
`titles[doc]['secnumber']`.

### 4.3 Translator lookups keyed by *resolved-tree* ids
- `get_secnumber` for a section title: `'#' + section['ids'][0]`, fallback `''`
  (`SP/writers/html5.py:406-425`). Consistent only if the transforms that change
  `section['ids'][0]` (`MoveModuleTargets`, `SortIds`) ran **before**
  `build_toc` — i.e. in the read phase, as in Sphinx.
- `add_fignumber` uses `node['ids'][0]` of the figure/table/container and
  **warns `Any IDs not assigned for %s node` when ids are empty**
  (`SP/writers/html5.py:435-457`, not gated on `numfig`). Without in-tree
  `PropagateTargets`, a `.. _x:`-labelled figure has empty `ids` in our tree
  → spurious warning + missing number. Without `AutoNumbering`
  (`SP/transforms/__init__.py:200-214`, read @210: captioned enumerable nodes with
  no ids get `note_implicit_target` → `id1`…), an unlabeled captioned figure has no
  ids here, while Sphinx gives it `ids="id1"` (probe1 `sub/b`: `<figure ids="id1">`).

## 5. Metadata

- Collector: `crate:src/env/metadata.rs:65 document_metadata`: leading
  `field_list` (after skipping PreBibliographic nodes) → `field_name.astext() →
  field_body.astext()`, `BTreeMap<String,String>`.
- Sphinx (`SP/environment/collectors/metadata.py` `process_doc`) reads the
  `docinfo` node docutils' `DocInfo` transform built, and **pops it from the
  doctree**. Probe3 exact results:
  `{'a': {'tocdepth': 0, 'author': 'Jane Doe', 'authors': ['A', 'B'], 'version': '1.2', 'custom field': 'x', 'nocomments': ''}, 'd': {'orphan': '', 'tocdepth': 2}, 'c': {}, 'b': {}}`
  for sources `":tocdepth: abc\n:author: Jane Doe\n:authors: A; B\n:version: 1.2\n:custom field: *x*\n:nocomments:\n\nA\n=…"`,
  `":orphan:\n:tocdepth: 2"` after a comment, and title-then-`:orphan:`.
  Differences: `tocdepth` is `int` (`int(value)`, `ValueError → 0`); bibliographic
  fields become class-named keys (`author`, `version`, …) and `authors` a list;
  insertion-ordered dict vs our sorted map.
- **Consumers:** `tocdepth` → `document_toc` and `_toctree_standard_entry`
  (`env.metadata[ref].get('tocdepth', 0)`, `SP/environment/adapters/toctree.py:57,348`)
  — our value is a `String`, parse with Python `int()` semantics (strip, sign,
  underscores; failure → 0; missing → 0). `nosearch`/`no-search` → search indexer
  (`SP/builders/html/__init__.py:1017`). `orphan` → `check_consistency`
  (`crate:src/env/toctree.rs:878-881`). Whole dict → `meta` template variable.
- **Docinfo removal gap:** we leave the field list in the tree → the writer would
  render it as a `<dl class="field-list">`; Sphinx never renders it. This is
  `KNOWN_RESOLVED_GAPS` `(orphan_doc, orphan)`.
- **Correction to `crate:src/env/metadata.rs:21-32`** ("Known gap — a field list
  below a promoted document title is not seen … closes by itself the moment
  doctitle promotion lands"): Sphinx sets `doctitle_xform = False`

## 9. The resolve pass and the URI model

### 9.1 What `crate:src/env/resolve.rs` does
`resolve_document` (`:777-801`): recursive walk (`resolve_children`, `:850-887`)
replacing every `pending_xref` via `resolve_one` (`:891-1134`) — intersphinx
`:external:` first, `:any:` (`resolve_any_ref`, `:1264`), non-{"",std,py} domains

`propagate_desc_domain` (`:831-847`, the `PropagateDescDomain` post-transform).

Node materialization (`reference_node`, `:1697-1727`): `reference` or
`number_reference`, `internal="1"`, `refid` XOR `refuri`, optional `title`
(numref format string), optional `reftitle` (py), children = contnode / fresh
`inline` with classes / adopted `pending_xref_condition` children.

refid/refuri rules (identical to Sphinx):
- `make_refnode` (`:425-445`, Sphinx `SP/util/nodes.py:653`): same doc and a

### 9.4 Resolved-doctree storage
`xref_phase` clones each doctree, resolves it, and keeps only
`doctree.root.pformat()` in `SphinxBuilder.resolved: Mutex<BTreeMap<String,String>>`
(`crate:src/builder.rs:133-138,1329-1348`). The writer needs the resolved `Doctree`.

### 9.5 Warning-order note (latent)

walks `findall(pending_xref)` in pre-order. Identical whenever a parent does not
hold both direct and deeper xrefs (true for the corpus); for byte-parity of the
warning stream on odd trees, switch to a pre-order sweep.

## 11. Porting spec: toctree resolution (`SP/environment/adapters/toctree.py`)

Everything below reads only: `env.tocs`, `env.titles`, `env.metadata` (tocdepth),
`env.toctree_includes` (ancestors), `config.include_patterns`/`exclude_patterns`
(only in the KeyError message path), builder URIs, builder tags. No `Node` parent
pointers exist in this crate (`crate:src/doctree/mod.rs:97-104`), so the "walk up"
steps below must be done by recursion with a returned flag or an index path.

### 11.1 `_resolve_toctree(env, docname, builder, toctree, *, prune, maxdepth, titles_only, collapse, includehidden, tags)` (`:119-221`)
1. `if toctree['hidden'] and not includehidden: return None`.
2. `ancestors = _get_toctree_ancestors(toctree_includes, docname)` (= `toctree_ancestors`).
3. `maxdepth = maxdepth or toctree.get('maxdepth', -1)`; `titles_only |= toctree['titlesonly']`; `includehidden |= toctree['includehidden']`.
4. `tocentries = _entries_from_toctree(…, toctree, parents=[])`; if empty → `None`.
5. `newnode = compact_paragraph()`; if `caption` truthy (not the "True" sentinel!) append `title(caption)` (text = caption); extend with tocentries; `newnode['toctree'] = True` (pformat `toctree="1"`).
6. `_toctree_add_classes(newnode, 1, docname)`.
7. `newnode = _toctree_copy(newnode, 1, maxdepth if prune else 0, collapse, tags)`.
8. If the last child is an Element with no children (empty `bullet_list`) → `None`.
9. For every `reference` in `newnode` (pre-order, any depth): if `refuri` is not a URL (`url_re = (?P<schema>.+)://.*`, `match`) → `refuri = get_relative_uri(docname, refuri) + anchorname`.

### 11.2 `_entries_from_toctree(…, toctreenode, parents, subtree=False)` (`:223-306`)
For each `(title, ref)` in `toctreenode['entries']`:
- `toc, refdoc = _toctree_entry(...)`; on `LookupError` skip the entry.
- If `titles_only`: for each top-level child of `toc` with `len > 1`: if it contains
  toctrees (findall), replace `top_level[1]`'s children with those toctree nodes;
  else pop `top_level[1]`.
- For every `toctree` node inside `toc` (`list(toc.findall(toctree))`, pre-order):
  skip if hidden and not includehidden; else splice its entries
  (`_entries_from_toctree(…, sub, [refdoc, *parents], subtree=True)`) into its
  parent right after it, then remove it.
- `entries.extend(toc.children)`.
Return `[bullet_list(entries)]` if not subtree, else the flat entries.

### 11.3 `_toctree_entry(title, ref, …)` (`:309-384`) — four kinds
- URL (`url_re.match(ref)`): `_toctree_url_entry` → `bullet_list > list_item > compact_paragraph > reference(internal=False, refuri=ref, anchorname='')` with text `title or ref` (pformat `internal="0"`).
- `self`: `_toctree_self_entry(title, toctreenode['parent'], titles)` → same shape, `internal=True`, `refuri=parent`, text `title or clean_astext(titles[parent])`, no sub-entries.
- virtual (`genindex`/`modindex`/`search`, the `_virtual_doc_names` KEYS, `SP/domains/std/__init__.py:784-788`): `_toctree_generated_entry` → `refuri` = `genindex`/`py-modindex`/`search`, text `title or` `Index`/`Module Index`/`Search Page`.
- document: if `ref in parents` → **warning** `circular toctree references detected, ignoring: {ref} <- {' <- '.join(parents)}`, `location=ref` (a docname → rendered as `doc2path(ref)` **with no line**), `type='toc', subtype='circular'` → `[toc.circular]`; raise LookupError. Else `_toctree_standard_entry(title, ref, metadata[ref].get('tocdepth', 0), tocs[ref], ancestors, prune, collapse, tags)`.
- After building: `if not toc.children:` → **warning** `toctree contains reference to document %r that doesn't have a title: no link will be generated`, `location=toctreenode` (the toctree's source:line), `[toc.no_title]` — the entry is still returned (contributes nothing).

(Near-unreachable here: `includefiles` only lists found docs.)

### 11.4 `_toctree_standard_entry` (`:431-452`)
`if ref in ancestors and (not prune or maxdepth <= 0): toc = deepcopy(tocs[ref])`
else `toc = _toctree_copy(tocs[ref], 2, maxdepth, collapse, tags)` — `maxdepth`
here is the REFERENCED document's `tocdepth` (default 0). Then if `title` and
exactly one top-level child: every `reference` in it with `refuri == ref` and
empty `anchorname` gets its children replaced by `Text(title)` (attributes such as

### 11.5 `_toctree_add_classes(node, depth, docname)` (`:455-482`)
For each child: `compact_paragraph`/`list_item` → append class `toctree-l{depth-1}`
then recurse with the same depth; `bullet_list` → recurse with `depth+1`;
`reference` with `refuri == docname` (pre-rewrite refuri IS a docname):
- if `anchorname` empty → append `current` to the reference and EVERY ancestor up
  to the root `compact_paragraph` (duplicates allowed);
- then if `reference.parent.parent` (its `list_item`) already has `iscurrent` →
  **return from this recursion level**; else set `iscurrent=True` on the reference
  and every ancestor to the root.
Result (oracle `toctree_circular/a`): `<compact_paragraph classes="current" iscurrent="1" toctree="1">`,
`<list_item classes="toctree-l1 current" iscurrent="1">`, sibling
`<compact_paragraph classes="toctree-l1">` untouched, deepest
`<reference anchorname="" classes="current" internal="1" iscurrent="1" refuri="">`.

### 11.6 `_toctree_copy(node, depth, maxdepth, collapse, tags)` (`:485-560`)
`depth = max(depth-1, 1)`; `_toctree_copy_seq(node, …, initial_call=True)`:

- `reference`/`title`: shallow copy + deep-copied children.
- anything else: `ValueError('Unexpected node type …')`.

## 14. Gotchas checklist for implementers

1. Keep the env oracle on the dummy policy (URIs `''`, tags `{'', 'dummy', 'format_', 'builder_dummy'}`); add `-b dummy` if convenient — ROADMAP M2 already lists it.
2. Port `relative_uri` and `quote` verbatim; do not use `crate:src/utils.rs:563`.
3. `longtitles` must carry the `secnumber` stamp (or alias `titles`).
4. Decode `secnumber` (`List` vs `"True"`), `caption` (`"True"` = None), `entries` (tuple reprs, with a full `\x/\u/\U` inverse).
5. `tocdepth` is a string here; Sphinx uses `int()` with 0 on failure and 0 when absent.
6. Toctree resolution needs builder tags for `only`; the global toc deliberately ignores `only` wrappers around toctree nodes in the root doctree.
7. Template `toctree()` must share the warning sink — warnings repeat per rendered page in Sphinx.
8. `relations` includes virtual docnames (`genindex`, `modindex`, `search`) as nodes; `titles[...]` KeyError there means "no link", not a crash.
9. `toctree_circular` cannot be built by Sphinx's HTML builder at all (RecursionError); do not put it in an HTML oracle.
10. Resolution warnings are per-document, docname-sorted; genindex warnings come last (finish). Sphinx runs `check_consistency` only when something was re-read (`SP/builders/__init__.py:420-433`); the crate runs it on every build (warm-build warning difference).
11. `read_one_file`'s `cached.html.is_empty()` miss test (`crate:src/builder.rs:844`) must change when page rendering leaves the read phase; `Document.html` should stop being the cache-validity marker.
12. The toc anchors, `toc_secnumbers` keys and `toc_fignumbers` keys are all derived from ids; apply `MoveModuleTargets`/`Reorder…`/`PropagateTargets`/`SortIds`/`AutoNumbering` at read time, before `build_toc`, or the writer's `'#'+ids[0]` lookups diverge.
13. `std.labels` must keep the preseeded `py-modindex` label even when no module index page is written (Sphinx's inventory always lists it).
14. `rawentries`/`rawcaption` on toctree nodes are wrong in the parse layer (§2.2) — fix before any oracle records a captioned/titled toctree's `tocs_pformat`.
15. The genindex/py-modindex template contexts need Python-tuple-shaped (array) data, not the serde struct objects.
