# reporter-oracle — summary, key facts, risks

(a) REPORTER CHANNEL. docutils Reporter.system_message writes msg.astext()+'\n' to its stream AT CREATION (DU/utils/__init__.py:213-215) iff level>=report_level (2, docutils default; Sphinx pins none) or >=halt_level (5, SP/environment/__init__.py:72). Sphinx's LoggingReporter stream is WarningStream (SP/util/docutils.py:385-393): report_re (:31-33) strips 'source:line: (TYPE/N) ', message=rest.rstrip(), logger.log(TYPE, message, location='source:line', type='docutils'). Printed line: '{source}:{line}: {WARNING|ERROR|CRITICAL}: {astext-at-creation} [docutils]'; SEVERE->'CRITICAL: ' (LEVEL_NAMES logging.py:30-40, prefix :116-126); no line -> '{source}:: ERROR: ...' (double colon, probed on 'Anonymous hyperlink mismatch'). INFO/DEBUG never print (only as -vv '[filtered system message]' debug lines on stdout). All of WARNING/ERROR/CRITICAL increment _warncount (WarningSuppressor logging.py:429-450): exit 0 without -W ('build succeeded, 20 warnings.'), -W -> 'build finished with problems, 20 warnings (with warnings treated as errors).' exit 1; -w file is cmp-identical to stderr; suppress_warnings=['docutils'] silences the channel.
KEY QUIRK: DirectiveError messages (self.error()/severe() in run()) are created then get the literal_block appended (DU states.py:2286-2290) so the PRINTED text lacks the literal while the tree has it; 'Unknown directive type' and option-parse 'Error in "x" directive' pass the literal at creation and print it. Measured: over 1224 corpus cases (735 docutils + 489 sphinx) stream order == doctree order and membership == tree membership; the ONLY differences are those DirectiveError literals (28+11 cases). Crate's only such site: directive_run_message (src/rst/block.rs:6959-6968). Created-but-discarded messages still print (':caption: .. foo::' prints 'ERROR: Unknown directive type "foo".' from the throwaway nested parse plus 'WARNING: Invalid caption: ...').
ORDER: read-phase warnings buffered (pending_warnings, SP/builders/__init__.py:403-409) and flushed in order; docs read sorted (:512). Per doc: parse-time records (reporter + logger: toctree, py/std object duplicates, literalinclude reader) interleaved by creation -> transform-time by priority (Substitutions 220, AnonymousHyperlinks 440, UnreferencedFootnotesDetector 622, Transitions 830) -> SphinxDanglingReferences 850 -> SphinxDomains 850 (index then std process_doc) -> DoctreeReadEvent 880 (image not readable) -> FilterSystemMessages 999 (strip level<5 by default, <2 with keep_warnings). PATHS: location is the node source verbatim; included content = docutils relative_path(None, abs) = cwd-relative, absolute if cwd top-level dir differs (probed from 3 cwds); crate's srcdir-relative Scope-8 spelling equals Sphinx only when cwd==srcdir.
CRATE TODAY: report_parse_warnings (src/builder.rs:1107-1172) prints toctree warnings then log_warnings; no system_message is ever printed or counted; BuildWarning::render (src/error.rs:134-151) is WARNING-only; KNOWN_WARNING_GAPS inc_basic exists only for this; keep_warnings is in KNOWN_INERT_CONF because no FilterSystemMessages exists; M1 validators emit non-Sphinx duplicates of docutils errors ('Note directive requires content').
CHANGE: record level>=2 messages at creation (ReporterRecord{seq,level,source,line:Option,text}) with a seq shared by toctree warnings, ParseLogWarning and py/std registration records; carry in RegistryExport (cache-shape rule: no serde(default)); level-aware BuildWarning with raw location + [docutils]; emit seq-sorted in merge phase before index/std process_doc; count as warnings never BuildErrorReports; add keep_warnings + FilterSystemMessages before store_doctree (bump DOCTREE_FORMAT_VERSION); reconcile validators; fix env test (delete inc_basic gap, line-split rendered records or add warning_records to fixture). Exact inc_basic expected records captured.
(b) ORACLE: extend existing fixtures for the channel (docutils 'stream', sphinx per-case 'warnings', env 'warning_records'). HTML oracle: SphinxTestApp(buildername='html') with html_theme='basic', smartquotes=False, highlight_language='none'; instance handle_page override captures addctx (body/toc/title/prev/next/parents/rellinks/sourcename/metatags/...), html-page-context captures merged ctx; files walked after build. ## Risks and open questions

- The research note file itself could not be written (harness blocks .md report files from subagents); the orchestrator must persist these structured fields if implementers need a file. Probe scripts and outputs are at /tmp/claude-0/-home-user-sphinx-ultra/46bf5e6b-694f-5b8e-ba0d-36f1851a8974/scratchpad/probe-reporter-oracle/.
- Path-spelling decision (§Scope-8): Sphinx prints included-content reporter locations and include-error message paths via docutils relative_path(None, abs) — cwd-relative, or absolute when the cwd's top-level dir differs. The crate prints srcdir-relative, identical only when cwd==srcdir. Porting relative_path at render time fixes the location, but the path inside SEVERE texts is baked at parse time/cached; decide between a documented divergence and render-time substitution.
- Crate-side creation order vs docutils creation order: tree order == docutils stream order on all 1224 corpus cases, but recording at creation in the crate risks crate-specific creation sequences (a helper builds a message before/after where docutils does). Mitigate with a per-case assertion that recorded order equals tree order (modulo DirectiveError literals) and, better, with the recorded docutils/sphinx streams added to the fixtures.
- Created-but-discarded messages (e.g. the ':caption: .. foo::' nested-parse ERROR at the directive's content-offset line) are printed by Sphinx but not produced by the crate today; porting needs the nested caption parse's real line bookkeeping. Likely to be ledgered in wave 5 rather than fixed.
- Moving py/std object-duplicate warnings to their parse-time seq position changes the current output order for documents that also have index warnings or reporter records; env corpus projects py_dup/inc_warn pin today's order and must still pass (they have no mixed cases) — add reporter_interleave (probe p6) to pin the new order.
- Validator overlap: once reporter messages print, the M1 validators (validate_directives default on) double-report problems docutils already reports, in non-Sphinx wording, doubling -W counts. Needs a product decision (drop overlapping checks vs default off in sphinx-build mode); tests/e2e_cli.rs:1301-1330 pins the current validator text.
- Exit-code policy: Sphinx exits 0 on ERROR/CRITICAL records without -W. Routing reporter ERROR/SEVERE into BuildErrorReport (to match the crate's 'stricter' policy) would fail builds Sphinx passes — needs an explicit decision; recommendation is warnings only.
- FilterSystemMessages changes persisted doctrees and resolved_pformat (INFO messages disappear from the crate's trees, matching Sphinx); some KNOWN_RESOLVED_GAPS entries or sphinx-corpus exclusions may flip and the strict tables will force updates. Requires DOCTREE_FORMAT_VERSION bump. KNOWN_INERT_CONF's comment about keep_warnings=False is wrong (it drops all levels, not 'below SEVERE').
- The env fixture's 'warnings' key is line-split with blank lines dropped (tools/gen_env_fixture.py:1698-1699), which hides record boundaries and blank lines inside multi-line reporter records; comparing against it requires the same lossy split on the Rust side. Adding 'warning_records' is recommended but is a fixture regeneration (extend-only policy permits adding keys).
- Transform-time reporter producers (Substitutions 220, AnonymousHyperlinks 440 with no line, IndirectHyperlinks 460, Footnotes 620, DocInfo 340, Transitions 830, SphinxDanglingReferences 850) are not ported; the channel design must leave slots for them after parse-time records and before index/std process_doc warnings. The no-line 'path::' render form is only reachable through them today.
- suppress_warnings (including the 'docutils' type) and docutils.conf report_level are unsupported by the crate; real projects using them will see extra reporter warnings. Out of wave-5 scope but user-visible once the channel prints.
- HTML oracle: the existing regen commands do not pin Pygments/alabaster/jinja2/snowballstemmer/babel/imagesize; an HTML fixture without pins will churn on a future uv resolution. Pygments tokenization of explicit languages and highlight_language='default' behavior (tokenize valid Python) need a highlighter-compatible implementation or narrow exemptions; base conf uses highlight_language='none'.
- CLI stderr is not byte-identical today regardless of the channel (env_logger prefix on warn!); only the -w file is a byte-exact sink. A byte-exact stderr would need a custom logger format.
- Open: whether wave 5 should target alabaster (Sphinx's default html_theme) parity at all; the proposal pins html_theme='basic' for v1, so a drop-in build of a project with no html_theme would still differ in layout.
